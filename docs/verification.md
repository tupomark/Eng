## Сквозная история

Home → Reader → слово `linger` → явный выбор значения → сохранение предложения → Smart Review → раскрытие значения → recognition-самооценка → перезагрузка → Core → оспаривание → пересчёт оценки и расписания.

Границы проверены так: пользовательское действие вызывает чистую доменную операцию, валидированное состояние записывается в browser repository, UI сообщает об успехе после записи, reload восстанавливает данные. HTTP API и удалённая БД в этом пути не участвуют.

E2E отдельно проверяет отсутствие дублей, отсутствие вымышленного прогресса writing/speaking, неизвестное слово, недоступное сохранённое значение перед доступным в очереди, клавиатуру и возврат фокуса из диалога, Command, сохранность повреждённых байтов localStorage и отказ записи из-за квоты без сообщения об успехе.

Доменные тесты проверяют независимость пяти навыков, идемпотентность event ID, даты повторений, исключение спорного наблюдения, канонический порядок событий при одинаковом времени, UTC-валидацию и согласованность источника/навыка. Storage-тесты проверяют отказ записи и защиту от устаревшего snapshot.

SQL-миграция действительно выполняется в PGlite — локальном PostgreSQL-движке. Тестовые `auth.users`, `auth.uid()` и роли заменяют Supabase Auth только в тесте. Проверены RLS всех восьми таблиц, владение двумя пользователями, составные FK, запрет межпользовательских ссылок, неизменяемость evidence для browser role, недоступность записи AI-оценок и проекций, retry key и владение апелляциями.

## Ограничения среды и воспроизводимость

Turbopack не смог создать внутренний процесс с локальным портом в sandbox. Использован документированный `next build --webpack`; dev-команда также использует Webpack. Сервер и браузерная проверка запускались с разрешением на локальный процесс/порт.

WebKit загружен в игнорируемую `.cache/ms-playwright`. Недостающие библиотеки Debian 13 извлечены в `.cache/browser-deps`, с проверкой SHA256 по официальным метаданным. Системные пакеты не изменялись. Фактический запуск и рендеринг WebKit проверены. В этой среде использована команда:

```sh
PLAYWRIGHT_BROWSERS_PATH=/workspace/lexis/.cache/ms-playwright \
PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 \
LD_LIBRARY_PATH=/workspace/lexis/.cache/browser-deps/root/usr/lib/x86_64-linux-gnu \
npm run test:e2e
```

Переменная `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS` обходит проверку глобального `ldconfig`, который не видит локальные библиотеки; она не заменяет проверку запуска. Обычный CI устанавливает зависимости через `playwright install --with-deps` и не использует этот обход.

## Что пока не проверено и не подключено

- Физический iPhone Safari: производительность, selection handles, динамическая клавиатура и реальные safe areas.
- Визуальное совпадение с исходными референсами: они запрошены, но не предоставлены.
- Supabase Auth, реальные JWT/RLS, удалённый repository и атомарный server projector. Подготовленная миграция не применена к внешней БД.
- AI, лицензированный словарь, произношение/TTS/STT и запись микрофона. Voice — визуальный прототип.
- Синхронизация устройств, восстановление JSON-импорта, облачный backup и production-наблюдаемость.
- GitHub remote, выполнение CI на GitHub и Vercel deployment.

Следующий проверяемый срез: application use cases с асинхронными командами → Supabase Auth в тестовом проекте → server repository и атомарная запись evidence/dispute/projection → реальные двухпользовательские RLS/JWT-тесты → браузерный сценарий с потерей сессии и сети. Публикация — отдельное согласованное действие.
