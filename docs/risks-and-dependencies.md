Новые pinned MIT-зависимости: `ts-fsrs@5.4.2` (FSRS-6), `fflate@0.8.3` (bounded ZIP), `fast-xml-parser@5.11.2` (строгий XML), `@supabase/ssr@0.12.7` и `@supabase/supabase-js@2.118.0`. Реальный package API проверяется по установленной версии; upstream main может описывать несовместимую будущую API. Это не подтверждение runtime/live capability.

Не устанавливать библиотеку только потому, что она входит в предпочтительный стек. Версии и наличие зависимости проверяются в lockfile. Провайдерские SDK должны оставаться за адаптерами. Новая зависимость оценивается по API, лицензии, размеру клиентского bundle и совместимости с целевыми платформами.

## Что нужно для настоящих интеграций

Для Supabase нужны согласованный проект, способ входа, окружения разработки/теста, правила session handling и доступ для проверки миграций. Ключ service role не передаётся клиенту. Для AI необходимы выбранный провайдер, бюджет, критерии оценки и условия использования учебных материалов. Для речи — поддерживаемые языки/акценты, политика микрофона, STT/TTS-провайдер и решение о хранении аудио. Для словаря — лицензия и документированный API.

Наличие SDK, интерфейса адаптера или env placeholder не подтверждает работающую интеграцию. Подключение считается выполненным только после реального запроса, проверки результата, сценария ошибки и отражения ограничений в продукте.

## Пределы локальной проверки

Unit-тесты подтверждают описанные правила и граничные случаи, SQL-тесты — выполнение миграции и ограничения в тестовой среде, Playwright — конкретные браузерные сценарии. Они не доказывают качество обучения, пригодность AI-оценки, безопасность будущей инфраструктуры или производительность на всех iPhone. Перед пилотом каждая такая гипотеза получает собственную проверку.

## Дополнительные фактические границы 24 октября

- Опциональный Auth ещё не изолирует browser-local stores по аккаунтам. До multi-user пилота нужны полный owner-scoped repository/cache/queue и запрет применения pending command под другим пользователем. Наличие login screen не закрывает R05/R30/E02/E24/E25.
- LocalStorage stores имеют stale-byte guard, но не атомарную межвкладочную compare-and-swap. Writing/media используют IndexedDB transactions; это не два устройства и не общий remote transaction.
- Существуют отдельные validated backups, но полного media/profile export→restore drill ещё нет. Browser eviction остаётся риском; пользователь должен сохранять исходники.
- Новые Settings/purge/PWA/Tutor workspaces проходят интеграцию. Составной модуль не закрывается статусом implemented-local его части. Все pending test/capture/live gates отражаются в PROGRESS.
- Операционные команды и порядок безопасного test release — в [operations](operations.md); runbook пока не проверен на размещённой инфраструктуре.

## Собственный словарь — фактические границы 25 октября

Пользовательский каталог снимает прежнее ограничение «учиться можно только на восьми seed-словах»: собственное определение с конкретным POS/sense ID участвует в Dictionary, Library и common task/FSRS практике. Это не расширение проверенного редакционного/лицензированного покрытия: содержание отмечено `user-authored`, closed-key успех проверяет воспроизведение собственной записи, а не её истинность. Для M01 live source/RU/audio/offline rights по-прежнему нужен отдельный поставщик и проверка.

## Общий local-profile recovery — границы 26 октября

Новый `.lexis` workflow объединяет выбранные local stores и private media; старое ограничение «только отдельные JSON backups» больше не описывает весь подготовленный код. Точный проверенный уровень нового среза и source SHA определяет PROGRESS. Сам формат/интерфейс не закрывает E23/FLOW-10 целиком: нужны actual export/restore/readback, archive/delete и производные lineage проверки.
